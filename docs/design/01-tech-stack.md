## 选型依据

### 1. 为什么选择 Tauri 而不是 Electron？

| 对比项   | Tauri 2.0      | Electron |
| -------- | -------------- | -------- |
| 打包体积 | ~10 MB         | ~150 MB  |
| 内存占用 | ~50 MB         | ~150 MB  |
| 启动速度 | 快             | 较慢     |
| 安全性   | 更安全（Rust） | 一般     |
| 系统集成 | 原生 Rust      | Node.js  |
| 学习曲线 | 需要 Rust 基础 | 纯 JS    |
| 社区生态 | 快速增长       | 非常成熟 |

**结论**：Tauri 在性能、体积、安全性上全面优于 Electron。虽然需要 Rust，但 Tauri 2.0 已经封装好了大部分功能，前端开发者几乎不需要直接写 Rust 代码。

### 2. 为什么选择 Vue 3 而不是 React？

| 对比项          | Vue 3         | React      |
| --------------- | ------------- | ---------- |
| 学习曲线        | 平缓          | 较陡       |
| 代码风格        | 模板 + 组合式 | JSX        |
| TypeScript 支持 | 原生优秀      | 需要配置   |
| 响应式系统      | 自动追踪      | 手动依赖   |
| 生态完整性      | 官方维护      | 社区碎片化 |

**结论**：用户已经熟悉 Vue，选择 Vue 3 可以零学习成本直接上手。Vue 3 的 Composition API 在复杂状态管理上表现优异。

### 3. 为什么选择 Shadcn-Vue 而不是 Element Plus / Naive UI？

| 对比项           | Shadcn-Vue | Element Plus | Naive UI |
| ---------------- | ---------- | ------------ | -------- |
| 设计风格         | 现代极简   | 传统企业     | 现代科技 |
| 定制性           | 极高       | 中等         | 中等     |
| 包大小           | 按需引入   | 较大         | 中等     |
| TailwindCSS 集成 | 原生       | 需要配置     | 不支持   |
| 代码可控性       | 源码级     | 组件级       | 组件级   |

**结论**：Shadcn-Vue 不是传统组件库，而是可复制的组件代码，提供最大的定制自由度，与 TailwindCSS 完美配合，设计感最强。

### 4. 为什么选择 Pinia 而不是 Vuex？

- 更简洁的 API
- 完美支持 TypeScript
- Composition API 风格
- 更小的体积
- Vue 官方推荐

## Rust 后端职责

虽然我们主要使用前端开发，但以下功能需要在 Rust 侧实现：

| 功能     | 说明                         |
| -------- | ---------------------------- |
| 进程管理 | 启动/停止 N_m3u8DL-RE 子进程 |
| 输出解析 | 实时解析子进程输出           |
| 文件操作 | 读取/写入配置文件            |
| 系统集成 | 系统托盘、开机启动等         |
| 剪贴板   | 监听剪贴板 URL               |

Tauri 2.0 已经提供了大部分功能的 JavaScript API，我们只需要在 Rust 侧实现少量自定义命令。
